2. What riffbox is

riffbox is a locally operated software pipeline. It

  • finds popular gaming clips and trends via the platforms' official APIs,
  • processes only video material for which the rights holder has given permission or that originates from the operator,
  • turns this material into short reaction videos and longer compilations in which a fictional, AI-generated 2D avatar comments on it with a synthetic voice,
  • publishes the finished videos to the operator's own accounts on YouTube, TikTok, Instagram and X via the platforms' official APIs, only after the operator has manually approved each video,
  • retrieves performance metrics of the operator's own videos and can read comments under those videos.

Who uses riffbox: only the operator, with the operator's own accounts (possibly several per platform). There is no sign-up, no user accounts for third parties, and the software is not provided to anyone else.

Where riffbox runs: on the operator's own server in Germany, optionally on the operator's own laptop. The only externally reachable component is short-lived signed links for finished videos (see Processors).

4. riffbox software – general processing

4.1 Origin of video material

riffbox does not download video files from YouTube, Twitch or any other platform. These platforms' APIs are used only to discover clips and trends, retrieve metadata and publish the operator's own videos.

Video material of other people is used only if

  • the rights holder (e.g. the streamer) has expressly permitted the use and provides the file themselves, for example via a link they share, or
  • the material is under a licence that expressly permits this use.

riffbox also uses the operator's own material, such as the operator's own gameplay recordings.

4.2 Workflow

  1. Discovery: public clips, videos and posts on a topic are found as trend and source signals via the official APIs of Twitch, YouTube and, where applicable, Reddit. Only metadata is retrieved.
  2. Permission: for a desired clip, the operator requests permission from the rights holder. Permissions granted are documented in the creator register.
  3. Intake: the rights holder provides the file. It is stored in a local data folder outside the code repository.
  4. Analysis: the software creates a transcript, still frames (keyframes) and highlight markers locally. It automatically checks the material for exclusion criteria, such as slurs, hate speech, sexual content, gambling, real-world violence, drugs, visible personal data, minors and protected music.
  5. Creator register: check against an internal list (allowed / blocked / neutral). Material from blocked creators is not used; material without documented permission is not processed.
  6. Production: script, review of the generated text, speech synthesis, avatar animation and editing.
  7. Review queue: the operator manually reviews every video and approves it per platform.
  8. Publishing: upload via each platform's official API to one of the operator's own accounts.

7. Use of AI

7.1 What AI does in riffbox

  • Avatar: the commentator is a fictional, AI-generated 2D avatar. It does not depict or imitate any real person.
  • Voice: the voice is synthetic. It is an own, licensed or base voice of the model used, not a clone of a real person.
  • Locally run models (on the operator's server, no data sent to third parties): speech recognition, speech synthesis, optional image description, avatar creation with a custom character model trained only on images of the fictional character, lip sync, scene and highlight detection, and optionally a local language model.
  • External AI service: Anthropic (Claude), used for planning, scriptwriting and analysis.

7.2 Data sent to Anthropic

  • transcripts of the material used (containing statements by streamers and teammates)
  • still frames from the material (may show faces)
  • clip metadata including channel and display names
  • selected comments under the operator's videos, including display name
  • avatar persona description, format guidelines, metrics of own videos

No credentials, tokens or passwords are sent.

Role and terms: riffbox uses Anthropic only through a commercial API account. Anthropic processes the data as a processor under Anthropic's commercial terms of service and Data Processing Addendum. Under these terms, Anthropic does not use the content to train its models and by default deletes inputs and outputs within 30 days. Exceptions apply where content is reviewed on suspicion of usage-policy violations or where longer retention is legally required.

Legal basis: Art. 6(1)(f) GDPR; processing on behalf under Art. 28 GDPR.

7.3 No automated decisions about individuals

AI models automatically check content against exclusion criteria and suggest clips and texts. Every video is manually reviewed and approved by the operator before publishing. There is no automated decision producing legal effects or similarly significant effects on individuals within the meaning of Art. 22 GDPR.

7.4 Protection against manipulated input

Incoming texts (transcripts, comments) are checked for manipulation attempts (prompt injection) before AI processing.

11. Security

  • API keys, client secrets and tokens are stored only on the operator's server, never in the code repository; file permissions allow access only by the operator; refresh tokens are encrypted.
  • Credentials are never entered into AI services.
  • Only the minimum necessary permissions are requested per platform.
  • Two-factor authentication on all platform and developer accounts.
  • No ports are reachable from the internet; the review interface is only reachable locally.
  • Third-party material is processed only in isolated containers.
